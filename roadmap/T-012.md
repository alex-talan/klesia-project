## Goal

Provide the reusable test infrastructure that every backend HTTP-pipeline test uses: an in-process host, **signed test tokens**, replaceable ports, test configuration and log capture — no real tenant, database or Azure resource (architecture plan §11.6).

## Context (read first)

- `klesia_api/CLAUDE.md` §7; architecture plan §11.6; `integration-test` skill Level 1; API spec §10 (AT matrix) and AUTH-IMPL.
- Packages already central: `Microsoft.AspNetCore.Mvc.Testing`, xUnit, FluentAssertions, NSubstitute (add `NSubstitute` reference to the integration project if missing).

## Scope

- **In:** `KlesiaApiFactory : WebApplicationFactory<Program>`, `TestTokenFactory`, test configuration, `TestLogSink`, helpers to register fakes; one smoke test.
- **Out:** the tests of each feature (written by the feature tasks).

## Plan of actions

1. `KlesiaApiFactory`: environment `Testing`; in-memory configuration with syntactically valid fake values for every §6.1 key (tenant/client GUIDs, `https://test.blob.core.windows.net`, container `bae`, DI endpoint, SignalR endpoint, `Cors:AllowedOrigins` = `["http://localhost:5173"]`, connection string without password).
2. `TestTokenFactory`: generates an RSA key at startup; issues JWTs (via `Microsoft.IdentityModel.JsonWebTokens`, transitively available) with configurable `iss`, `aud`, `tid`, `oid`, `scp`, `exp`, `nbf`, `nonce`, signature (valid / other key / none). Default = a valid v2 access token for the test tenant and API.
3. Override JWT validation in the factory (`PostConfigure<JwtBearerOptions>`): set the signing key and a static `OpenIdConnectConfiguration` so no metadata is fetched (no network). Keep issuer/audience/lifetime validation identical to production. (Before T-018 exists, provide the hook; T-018 wires it.)
4. Fakes registration API: `factory.WithServices(s => s.Replace(...))` helpers for repositories and ports (`IUserRepository`, `IDemandRepository`, `IBaeDocumentStore`, `INotifier`, `IExtractionQueue`, `IDocumentExtractor`, `IDemandExtractionRepository`) — add the helpers as each port appears; provide in-memory implementations in `tests/IntegrationTests/Fakes/` as needed by feature tasks.
5. `TestLogSink`: an `ILoggerProvider` capturing formatted messages and structured state, so tests can assert that logs **do not** contain tokens, GK numbers, blob URLs (used by T-014, T-067).
6. Smoke test: the host starts with the test configuration; `GET /openapi/v1.json` is not exposed in `Testing` (only Development).
