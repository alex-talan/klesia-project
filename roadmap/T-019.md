## Goal

Require the delegated scope `access_as_user` (configuration `AzureAd:RequiredScope`) through a `DelegatedUser` policy that is both the default and the **fallback** policy, so any new endpoint is protected unless explicitly anonymous; a valid token without the scope gets `403` problem+json.

## Context (read first)

- API spec §4.1 point 4 and AUTH-IMPL (*Scope*), §4.3, DEC-11, AT-04; architecture plan §9.2 (secure by default).

## Scope

- **In:** policy, fallback, `403` body (identical text that T-021 will reuse), tests.
- **Out:** allowlist.

## Plan of actions

1. `DelegatedUser` policy: authenticated user and a `scp` claim whose space-separated values contain `RequiredScope` (exact, case-sensitive). Application-only tokens (no `scp`, `roles` only) fail.
2. `options.DefaultPolicy = options.FallbackPolicy = DelegatedUser`.
3. Forbidden response: customise `IAuthorizationMiddlewareResultHandler` to write problem+json `403` with a **constant** `title` ("Forbidden") and no `detail`; define this body in one place (e.g., `Problems.Forbidden()`) so the allowlist `403` (T-021) is byte-identical except `traceId`.
4. Mark `/health` and the OpenAPI document (Development) `AllowAnonymous` explicitly (health route arrives in T-022 — add the attribute there).
5. Tests: token without `scp` → `403`; with `scp` = `other` → `403`; with `scp` = `foo access_as_user` → allowed; unknown route under `/api/v1/...` without a token → `401` (fallback policy applies); bodies `application/problem+json`, `traceId` present.

## Acceptance criteria

- [ ] AT-04 passes; application-only tokens are `403`.
- [ ] Fallback policy protects every endpoint not marked anonymous.
- [ ] Single definition of the `403` problem body.
