## Goal

Wire everything into the reference scenario: start the hub, send the initial GET once the first connection attempt settles (≤ 5 s), reload only on the four RT-04 triggers, **no GET on POST success**, stop the connection on unmount/sign-out.

## Context (read first)

- Webapp spec §1.1 (reference scenario), DEM-01, DEM-04, DEM-05, RT-01, RT-03 to RT-07, NEW-07, AC-06, AC-15, AC-22, AC-23, AC-36 to AC-40, AC-52, AC-53, AC-54; architecture plan §2.2, §7.4.

## Scope

- **In:** orchestration in `App.vue` (or a `useRealtimeDemands` composable), modal open/close wiring with the "Nouvelle demande" button, integration-style component tests `tests/components/App.spec.ts` with a fake hub and mocked services.
- **Out:** new behaviour not in RT-04.

## Plan of actions

1. After authentication: `realtimeService.start(onNotification = reloadDemands, onStateChange = set connection state)`; await its settle (connected/failed or 5 s), then `reloadDemands()` (initial trigger).
2. `onReconnected` → `reloadDemands()`; `demandUpdated` → `reloadDemands()`; "Réessayer" → `reloadDemands()`. Nothing else calls it.
3. Modal: "Nouvelle demande" opens it; on `submitted` → close only (no reload, no local insertion). OK never disabled because of the connection state.
4. Unmount / sign-out → `realtimeService.stop()`.
5. Tests: AC-36 (initial GET after settle or after 5 s with fake timers), AC-06, AC-22 (burst of notifications), AC-23 (focus/visibility/timers → no GET), AC-52 (POST 2xx → zero GET; N-1 → one GET showing "En cours"; N-2 → one GET showing "Traitée"/"En anomalie"), AC-53 (POST while reconnecting → no GET; after reconnection one GET), AC-54 (notification during POST → one GET, POST response adds none), AC-37/AC-38 state lines, AC-40 (stop on unmount).
