## Goal

Implement operation `negotiateNotifications`: protected exactly like the REST routes (allowlist included), it returns the SignalR redirect negotiation `{ "url", "accessToken" }` for hub `demands` with `userId` = the validated `oid`.

## Context (read first)

- API spec §8.1 (all bullets), §5.2 (CORS headers, `negotiateVersion=1`), DEC-09, AT-18, AT-31, AT-32; contract `negotiateNotifications`, schema `NegotiateResponse`; webapp spec BE-01, BE-06; [ARB-004](ARB-004.md).

## Scope

- **In:** an Application port for negotiation (e.g., `IRealtimeNegotiator.NegotiateAsync(Guid oid, ct)` → `(Uri Url, string AccessToken)`), its Infrastructure implementation on the shared SignalR service client of T-030, a `NotificationsController`, tests.
- **Out:** any other SignalR route; any unprotected `/negotiate`.

## Plan of actions

1. Application use case `NegotiateNotificationsAsync(oid)`: resolve user (allowlist, T-021: inactive → `403`), then call the negotiator with `user.UserUniqueId`.
2. Infrastructure: SDK negotiation for hub `demands` with `UserId = oid.ToString()` (e.g., `ServiceHubContext.NegotiateAsync(new NegotiationOptions { UserId = … })`); returns the service client URL and a short-lived token. Never return or log the token, the URL or any key.
3. Controller: `[HttpPost("api/v1/notifications/negotiate")]`, no body expected, accept any query (`negotiateVersion=1`); response record with **camelCase** names `url` and `accessToken` declared explicitly (DEC-09 exception); `200 application/json`.
4. Errors: `401`/`403` as other routes; SignalR failure → `503`/`500` sanitised problem (choose `503` for service unavailable and document it; the contract documents the codes — use only documented ones).
5. Tests (negotiator faked): AT-31 (`200`, exactly `{url, accessToken}`, negotiator called with the token's `oid` — not a client value); AT-18 (`401` without token, `403` scope, `403` unknown and inactive user; negotiator not called); AT-32 (preflight with `X-Requested-With`, `X-SignalR-User-Agent`, no credentials header); `?negotiateVersion=1` accepted; empty body accepted; logs contain no token.

## Acceptance criteria

- [ ] AT-18, AT-31, AT-32 pass.
- [ ] `userId` is the validated `oid`; no other source.
- [ ] Response names exactly `url`, `accessToken`; no secret ever returned or logged.
