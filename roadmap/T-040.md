## Goal

Read and validate the six public `VITE_*` values once at startup and expose a typed, frozen configuration object — or a typed configuration error that the UI turns into a safe French message (AC-35, AC-50).

## Context (read first)

- Webapp spec §3.1 (exact names, API origin without path, hub URL without `/negotiate`, `https` in production, localhost `http` only in development), AC-35, AC-50, AC-43; contract `servers` (no `/api/v1`).

## Scope

- **In:** `environment.ts` (`loadEnvironment(env = import.meta.env)` pure function + exported result), `.env.example` with placeholders, unit tests `tests/unit/config/environment.spec.ts`.
- **Out:** UI rendering of the error (T-053).

## Plan of actions

1. Required: `VITE_API_BASE_URL`, `VITE_ENTRA_CLIENT_ID`, `VITE_ENTRA_TENANT_ID`, `VITE_ENTRA_REDIRECT_URI`, `VITE_API_SCOPE`, `VITE_SIGNALR_HUB_URL`.
2. Rules: non-empty; API base URL = origin only (no path other than `/`, no query/fragment, no `/api/v1`); hub URL absolute, path ends with `/api/v1/notifications` (no `/negotiate`); redirect URI absolute and ends with `/redirect.html`; tenant/client GUID-shaped; scope of the form `api://…/access_as_user` (or at least `api://` prefix and a scope segment); in production mode (`import.meta.env.PROD`) every URL must be `https:`; in development `http://localhost`/`127.0.0.1` accepted.
3. Return `{ ok: true, config }` or `{ ok: false, missingOrInvalid: string[] }` (variable **names** only, never values).
4. `.env.example` with the six names and obvious placeholders; never real ids.
5. Tests: valid dev and prod configs; each variable missing/empty; `http://` API in prod; API URL with path; hub URL ending with `/negotiate`; malformed URL.

## Acceptance criteria

- [ ] AC-35 and AC-50 logic covered by unit tests.
- [ ] Error lists names only.
- [ ] `.env.example` complete, no real values.
