## Goal

Add the global response headers of DEP-05 to `staticwebapp.config.json` with per-environment origins as placeholders, and the automated check AC-48.

## Context (read first)

- Webapp spec DEP-05, DEP-02, §4 (no COOP), AC-48, AC-57; architecture plan §9.4; [ARB-018](ARB-018.md) (how origins are injected per environment), [ARB-021](ARB-021.md) (PDF viewer).

## Scope

- **In:** `globalHeaders`: `Content-Security-Policy` (`default-src 'self'`; `script-src 'self'`; `object-src 'none'`; `base-uri 'self'`; `frame-ancestors 'none'`; `connect-src 'self' https://login.microsoftonline.com <API origin> <SignalR https> <SignalR wss>`; `style-src 'self'`; `img-src 'self' data:` only if needed — justify), `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy` denying unused features; placeholders for origins (e.g., `__API_ORIGIN__`) and the substitution approach decided by ARB-018 (default: pipeline substitution, documented); tests.
- **Out:** the actual per-environment values (T-086).

## Plan of actions

1. Verify the built app works with `script-src 'self'` and `style-src 'self'` (Vite extracts CSS; no inline scripts; MSAL bridge has no inline script).
2. Add headers; keep `/redirect.html` `no-store` and no COOP.
3. Decide whether a `frame-src`/`worker-src` is required by MSAL v5 (silent token renewal may use hidden iframes on the same origin or the redirect bridge — check MSAL v5 docs; add the minimal directive with a justification).
4. `tests/security/headers.spec.ts`: parse the JSON; assert presence of each header; no `unsafe-eval`; no `unsafe-inline` in `script-src`; no `*` in `connect-src`; no COOP; `/redirect.html` route `no-store`; placeholders present (or valid origins after substitution).
5. Document the substitution mechanism for T-086.

## Acceptance criteria

- [ ] App runs under the CSP in `vite preview` with headers emulated (or SWA CLI) — record how verified.
- [ ] No wildcard; no COOP.
