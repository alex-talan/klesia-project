## Goal

Consolidate the automated security checks AC-43 to AC-47 and AC-49 across the whole SPA (static scans and runtime spies), and get an independent security review.

## Context (read first)

- Webapp spec AC-43, AC-44, AC-45, AC-46, AC-47, AC-49, §8 last paragraph, §4; architecture plan §9.4, §9.5; Appendix A rows *Security*.

## Scope

- **In:** `tests/security/secrets.spec.ts` (AC-43), `storage-logging.spec.ts` (AC-44, AC-45), `rendering.spec.ts` (AC-46, AC-47), `token-routing.spec.ts` (AC-49); review report.
- **Out:** CSP (done in T-069).

## Plan of actions

1. AC-43: scan `src/`, `public/`, `.env.example` and `dist/` (after build) for `Endpoint=`, `AccessKey=`, `SharedAccessKey`, `client_secret`, JWT-shaped strings (`eyJ…\.…\.…`), real-looking GUIDs other than documented placeholders.
2. AC-44: run sign-in, GET, POST, real-time and document flows with spies on `localStorage`, `sessionStorage`, `document.cookie`, `history.pushState/replaceState`: no token, GK number, `bae_link` or object URL written (MSAL keys excluded).
3. AC-45: console spies (`log`, `info`, `warn`, `error`, `debug`) across auth, GET, POST failures, real-time, document failures: none contains a token, GK number, `bae_link`, hub/negotiate URL, payload or file content (sentinel values).
4. AC-46: static check that `src/` contains no `v-html`, `innerHTML`, `eval`, `new Function`; render fixtures with HTML/script/quotes/long values.
5. AC-47: render each malicious `bae_link`; no element with `href` bound to it; no request.
6. AC-49: spy on `fetch` and on the hub `accessTokenFactory`: the token goes only to the API origin (REST and PDF) and the negotiate endpoint; never to the negotiate-returned service `url` or any other host.
7. Ask `security-auditor` for a review; record findings and fixes.
