## Goal

Introduce `IDemandRepository` with its first operation: list all demands of one internal user id with their status code, newest first.

## Context (read first)

- API spec §5.1 processing rules 3, 5, 6, 8, 9; DEC-12 (`d.Id AS DemandId`); §3.4 (`IX_Demand_UserId` on `(UserId, Id DESC)`); DEC-22 (no extracted data); DB-10.

## Scope

- **In:** `IDemandRepository.ListByUserAsync(int userId, CancellationToken)`; Dapper implementation; registration; opt-in DB test.
- **Out:** document lookup (T-027), insert (T-033).

## Plan of actions

1. Application: `IDemandRepository` with `Task<IReadOnlyList<Demand>> ListByUserAsync(int userId, CancellationToken ct)`.
2. Infrastructure SQL (parameterised):
   `SELECT d.Id AS DemandId, d.GKNumber, s.Code AS StatusCode FROM dbo.Demand AS d INNER JOIN ref.Status AS s ON s.Id = d.StatusId WHERE d.UserId = @UserId ORDER BY d.Id DESC;`
3. Map rows to domain `Demand` (GK through `GKNumber`; `CHAR(18)` has no padding for valid values — still `TrimEnd()` is **not** applied: values are exact by the check constraint; status through `DemandStatus` parsing — an unknown code is a data-integrity fault → exception → `500`).
4. Never select `BaeLink` here (not needed for the list; DEC-24).
5. Register scoped in `AddInfrastructure`.
6. Opt-in DB test (skipped without `KLESIA_TEST_SQL_CONNECTION`): two users, ordering, isolation.

## Acceptance criteria

- [ ] Query filters on `UserId`, orders by `Id DESC`, selects no `BaeLink` and no extraction data.
- [ ] Parameterised; no interpolation.
- [ ] Build and tests pass.
