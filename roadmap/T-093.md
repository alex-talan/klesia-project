## Goal

Make the standard .NET logging abstraction available to Application so T-035 can log a sanitized best-effort cleanup failure through `ILogger<DemandService>`.

## Context (read first)

- [ARB-026](ARB-026.md) decision: Application uses `Microsoft.Extensions.Logging.Abstractions`, centrally pinned. The API host already configures structured console logging; Application must not depend on Infrastructure or WebApi.
- `klesia_api/Directory.Packages.props`, `klesia_api/src/Application/Application.csproj`, `klesia_api/src/Application/DependencyInjection.cs`.

## Scope

- **In:** central package version and Application package reference; verify Application builds and the logger is resolvable through the API host.
- **Out:** demand creation behavior, cleanup handling and its unit tests (T-035).

## Plan of actions

1. Follow the repository's version discipline and align the centrally pinned logging abstractions package with the existing .NET 10 Microsoft.Extensions package versions.
2. Add the package version to `Directory.Packages.props` and a versionless `PackageReference` to `Application.csproj`.
3. Verify that `ILogger<T>` is supplied by the existing host logging setup without adding an Application-to-Infrastructure dependency.
