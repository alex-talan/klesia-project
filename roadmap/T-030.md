## Goal

Implement `INotifier` with Azure SignalR Service in Serverless mode: a user-targeted `demandUpdated` message with **no arguments** on hub `demands`, authenticated with the managed identity, short timeout, never throwing into the caller.

## Context (read first)

- API spec §8.1 (identity, role), §8.2 (event contract), NOT-01 to NOT-05, AT-37, AT-38, HOST-04; contract *Real-time notifications*; [ARB-004](ARB-004.md) *Decision* (library and role).

## Scope

- **In:** the adapter, the shared SignalR service client (reused by T-031 for negotiation), DI registration in `AddInfrastructure`, tests with a faked transport.
- **Out:** negotiate endpoint (T-031), infrastructure (T-079/T-080).

## Plan of actions

1. Following ARB-004 (expected: `Microsoft.Azure.SignalR.Management`): build one `ServiceManager`/`ServiceHubContext` for hub `demands` from `AzureSignalR:Endpoint` with `DefaultAzureCredential` (no connection string, no key); singleton; disposed on shutdown.
2. `AzureSignalRNotifier.NotifyDemandsChangedAsync(oid)`: `Clients.User(oid.ToString())` `SendCoreAsync("demandUpdated", Array.Empty<object>(), ct)` with a **short timeout** (linked CTS, e.g., 5 s constant); catch every exception → log Warning *"notification failed"* with correlation/category only (no `oid` + GK/link combination; NOT-04) → return normally.
3. Never broadcast (`Clients.All` forbidden); method name exactly `demandUpdated`.
4. Testability: wrap the SDK behind a tiny internal interface (e.g., `IDemandsHubClient`) so tests can assert hub, method, arguments and target without network.
5. Tests: AT-37 (one message: hub `demands`, method `demandUpdated`, zero arguments, user = that `oid`, no broadcast); AT-38 (transport throws / times out → call returns without throwing, warning logged without user data, elapsed ≤ timeout + margin).
6. Package version pinned centrally.
