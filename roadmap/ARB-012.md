| Subject | Network topology and inbound exposure |
| Description | Public + firewall or VNet + private endpoints for SQL and storage; inbound exposure, domain, certificate (OPEN-07b, OPEN-08b/c, OPEN-12a) |
| Blocking | YES |
| Concerning tasks | `T-081`, `T-082`, `T-083` |
| Status | OPEN |

## Context

- HOST-10: the web app reaches Azure SQL (1433) and storage over TLS; outbound addresses are not a stable allowlist when the app scales; VNet integration with private endpoints is the preferred target for the database.
- DEC-24 / OPEN-12a: only the API reads the storage, so the account can be restricted to the App Service.
- OPEN-08c: inbound exposure (public endpoint, private entry, IP restrictions, custom domain, certificate).
- The browser must reach the API over HTTPS and Azure SignalR over WSS from the users' network (corporate proxies, DEP-03).

## Questions

1. SQL and storage: public endpoint with firewall rules, or VNet integration + private endpoints?
2. API inbound: public, IP-restricted, or behind a private entry point / gateway? Custom domain and certificate?
3. SignalR: public endpoint (needed by browsers) — confirm.

## Recommendation

VNet integration with private endpoints for SQL and storage; public HTTPS inbound for the API with a custom domain; public SignalR endpoint with CORS.
