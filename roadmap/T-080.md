## Goal

Define (or verify) one storage account per environment with one **private** container, anonymous access off, **shared-key access disabled**, no CORS, network restrictions per ARB-012 and data-protection settings per ARB-014.

## Context (read first)

- API spec DEC-24, OPEN-12, AT-57; architecture plan §4.3 point 4, §9.6; [ARB-012](ARB-012.md), [ARB-014](ARB-014.md), [ARB-020](ARB-020.md).

## Scope

- **In:** `storage.bicep` (account: `allowBlobPublicAccess: false`, `allowSharedKeyAccess: false`, `minimumTlsVersion: TLS1_2`, `supportsHttpsTrafficOnly: true`, redundancy, network rules/private endpoint, blob service soft delete/versioning, container with `publicAccess: None`), role assignment through T-079, outputs `BlobServiceUri` and container name for app settings.
- **Out:** lifecycle deletion rules unless ARB-020/ARB-014 require them.

## Plan of actions

1. Write the module with parameters per environment.
2. Validate (`az bicep build`, what-if).
3. After deployment by the operator (dev): run AT-57 manually — anonymous blob read, anonymous container listing and a shared-key-signed request are all refused; record results.

## Acceptance criteria

- [ ] Settings above enforced (or verified on the DSI resource).
- [ ] AT-57 run on the dev account (or reported *not run* with reason).

## Verification

`az bicep build`; AT-57 commands recorded.
