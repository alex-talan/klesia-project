## Goal

Create the `Domain` entities and value objects named by the architecture plan §6.1: `ApplicationUser`, `Demand`, `GKNumber`, `DemandStatus`, `DemandInformation`, `DemandFormula` — with no dependency on HTTP, SQL, Azure or SignalR (AP-03).

## Context (read first)

- Architecture plan §6.1 (layer content), §8.2 (identity distinction), §8.3 (status rules).
- API spec §3.2 (identity: `sec.User.Id` internal vs `UserUniqueId` = `oid`), §3.3 (GK number format, status codes), DEC-19, DEC-21.
- `klesia_api/CLAUDE.md` §2, §3 (nullable, small abstractions).

## Scope

- **In:** domain types + unit tests.
- **Out:** persistence mapping, DTOs, JSON attributes (WebApi), validation of extraction answers (T-038).

## Plan of actions

1. `src/Domain/Users/ApplicationUser.cs`: `int Id` (internal), `Guid UserUniqueId` (Entra `oid`), `string Name`, `bool IsActive`; immutable (record or class with init).
2. `src/Domain/Demands/GKNumber.cs`: value object wrapping a `string`; `static bool TryCreate(string? value, out GKNumber)` / `Create` validating `^GK[0-9]{6}-[0-9]{9}$` **case-sensitively** (no trimming, no upper-casing: the API does not normalise — contract *GK number* convention); `ToString()` returns the value unchanged. Use a source-generated `Regex` with a timeout or a manual check.
3. `src/Domain/Demands/DemandStatus.cs`: closed set `Pending`, `Ok`, `Fail` with code mapping `pending`/`ok`/`fail` (exact, case-sensitive); parsing an unknown code throws/returns failure (the API side is strict).
4. `src/Domain/Demands/Demand.cs`: `int Id`, `int UserId`, `GKNumber GKNumber`, `DemandStatus Status` (the internal blob URL is **not** part of the domain entity used for listing; keep it out unless a use case needs it — the document lookup returns it separately in T-027).
5. `src/Domain/Extraction/DemandInformation.cs` and `DemandFormula.cs`: properties mirroring §3.3 columns (PascalCase, nullable where the column is nullable; `Formulas` as an ordered read-only list).
6. Unit tests (`tests/UnitTests/Domain/…`): GK valid example `GK260902-144743112`; invalid cases from AT-24/§3.6 item 6 (lower-case `gk…`, letters, missing hyphen, 17/19 chars, embedded/leading/trailing space); status code round-trip and rejection of `OK`, `done`, empty.
7. Confirm `Domain.csproj` has no project or package reference.

## Acceptance criteria

- [ ] Types exist with the names above; `Domain` references nothing.
- [ ] GK validation is exact and case-sensitive; no normalisation.
- [ ] Status vocabulary is closed (three codes).
- [ ] Unit tests pass; build has no warning (warnings are errors).
