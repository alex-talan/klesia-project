## Goal

Make the user allowlist seed environment-aware as decided in ARB-019, keeping it idempotent and insert-only.

## Context (read first)

- API spec DEC-05, §3.5 (seed rules), §3.3 *Defaults note*; `Scripts/02_User.sql`; [ARB-019](ARB-019.md) *Decision*.

## Scope

- **In:** per ARB-019 (expected: a SQLCMD variable `Environment` declared in the `.sqlproj` and passed by `SqlPackage /v:Environment=…`; `02_User.sql` with one insert-only `MERGE` block per environment); documentation of the operator procedure for deactivation.
- **Out:** a user-management API (out of scope by spec).

## Plan of actions

1. Declare the SQLCMD variable in the project (`<SqlCmdVariable Include="Environment">`) with no default that could seed production by mistake (fail-closed: unknown value → no user seeded, and a `PRINT`/`RAISERROR` warning).
2. Restructure `02_User.sql`: per-environment `VALUES` lists, same insert-only `MERGE` matched on `UserUniqueId`, role by code.
3. Production list: only the values provided by the client (oids supplied; never invented).
4. Build; publish twice to a disposable database with each environment value (if EXT-004 available, else *not run*).
5. Update `docs/local-development.md` §5 and the deployment guide.

## Acceptance criteria

- [ ] Environment-specific seeding works; insert-only; idempotent.
- [ ] Unknown environment seeds nobody.
