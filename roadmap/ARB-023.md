# ARB-023 — Azure App Configuration and Key Vault adoption

| Field | Value |
|---|---|
| Number | ARB-023 |
| Subject | Azure App Configuration and Key Vault adoption |
| Description | Keep or remove the speculative `Azure:*` sections of `appsettings.json` |
| Blocking | NO |
| Concerning tasks | `T-007` |
| Status | OPEN |

## Context

- `klesia_api/src/WebApi/appsettings.json` contains `Azure:AppConfiguration:Endpoint`, `Azure:KeyVault:VaultUri`, `Azure:Storage:BlobServiceUri` and `Azure:ServiceBus:Namespace`.
- API spec §6.1 defines `Storage:BlobServiceUri` and `Storage:ContainerName` (no `Azure:` prefix), and no App Configuration, Key Vault or Service Bus setting: the API holds no secret (HOST-05), Service Bus only if ARB-008 decides so. `klesia_api/CLAUDE.md` mentions App Configuration "if adopted".
- AP-14: no speculative capability.

## Question

Is Azure App Configuration (or a Key Vault configuration provider) adopted?

## Provisional default (non-blocking)

Not adopted: T-007 removes the `Azure:*` sections and uses the §6.1 keys.

## Impact if settled differently

Follow-up task: configuration provider in `WebApi`, identity role on the App Configuration store, specification §6.1 update first.
