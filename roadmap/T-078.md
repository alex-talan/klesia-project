## Goal

Run both applications locally against real Entra ID and the dev Azure SQL, storage and SignalR resources, through a contract proxy, and exercise the reference scenario end to end (Level 3 of `integration-test`).

## Context (read first)

- `integration-test` skill Level 3; architecture plan §2.2; webapp spec INT-10 to INT-14, AC-49, AC-51; API spec AT-31 (real), DEC-24. Document Intelligence (EXT-007) is optional here: without it the extraction ends `fail`, which still exercises N-2.

## Scope

- **In:** local API (`http://localhost:5180`) with `appsettings.Local.json` (git-ignored) pointing to dev resources, the webapp (`npm run dev`) through a contract proxy (Prism if available), test users of EXT-002 in the dev allowlist (seed or operator insert).
- **Out:** production, committed tokens or identifiers.

## Plan of actions

1. Prepare the dev database (publish the DACPAC; add the test users).
2. Start the API; start the proxy (`npx @stoplight/prism-cli proxy contracts/openapi.yaml http://localhost:5180 --errors` — check flags with `--help`); start the webapp with `VITE_API_BASE_URL` = proxy URL and `VITE_SIGNALR_HUB_URL` = proxy URL + `/api/v1/notifications`.
3. Scenario with the active test user: sign-in; list loads; open a PDF (object URL tab); create a demand → modal closes with no GET; N-1 → "En cours"; N-2 → "Traitée" (with EXT-007) or "En anomalie" (without); duplicate GK allowed.
4. Negative: inactive user → `403` access denied and real-time "indisponibles"; non-allowlisted user → same; CORS from `http://localhost:5173` OK.
5. Inspect network traces: Entra token only in `Authorization` headers to the API origin and negotiate; only the SignalR connection token in the WebSocket URL (INT-13); notifications targeted (second browser with another user receives nothing).
6. Collect proxy violations (each is a finding → task).
7. Write a manual checklist report (`roadmap/reports/T-078-live.md`), with *not run* items explicit.
