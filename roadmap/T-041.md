## Goal

Run extractions in the background: a hosted `ExtractionWorker` reads demand ids from the queue and processes at most `Extraction:MaxConcurrency` at a time, each in its own DI scope, and stops cleanly on shutdown.

## Context (read first)

- API spec EXT-01, EXT-08, HOST-06, HOST-08, AT-47; architecture plan §10.2 (*Scaling*), §11.3.

## Scope

- **In:** `ExtractionWorker : BackgroundService`, registration inside an Infrastructure method `AddExtractionProcessing()` (service + worker), integration test with fakes.
- **Out:** sweep (T-042), real extractor (T-043).

## Wiring rule (important)

`Program.cs` must not register the extraction processing until a real `IDocumentExtractor` exists, otherwise the DI graph validation fails in Development. Therefore `AddExtractionProcessing()` is called by the **test host** in this task and added to `Program.cs` by **T-043**. Until then, enqueued ids are simply not consumed and the sweep (once wired) recovers them.

## Plan of actions

1. `ExecuteAsync(stoppingToken)`: consume `ReadAllAsync(stoppingToken)`; throttle with a `SemaphoreSlim(MaxConcurrency)`; for each id start a task that creates a scope, resolves `DemandExtractionService` and calls `ProcessAsync(id, stoppingToken)`; release the semaphore in `finally`; catch and log unexpected exceptions per item (demand id only) so one failure never stops the worker.
2. Shutdown: when `stoppingToken` is cancelled, stop reading; await in-flight tasks (they observe the token and return without status change — EXT-08); respect the host shutdown timeout.
3. Integration test (test host with fakes): enqueue ids → processed; with `MaxConcurrency = 2`, at most two concurrent `ProcessAsync` calls (blocking fake extractor); AT-47: stop the host while an extraction blocks → the fake repository records no `fail`, the demand stays `pending`.

## Acceptance criteria

- [ ] Concurrency bound respected; one failing item does not stop the worker.
- [ ] AT-47 passes.
