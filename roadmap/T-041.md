## Goal

Load `/config/app-config.json` at startup and validate `maxPdfSizeMb`; a failure disables PDF selection and submission only (AC-20).

## Context (read first)

- Webapp spec §3.2 (file, 1 MB = 1,048,576 bytes, missing/non-numeric/non-positive → configuration error, editable without rebuild), AC-20; architecture plan §6.2 (two configuration channels); [ARB-002](ARB-002.md) default 10.

## Scope

- **In:** `public/config/app-config.json` (`{ "maxPdfSizeMb": 10 }`), `runtimeConfig.ts` (`loadRuntimeConfig(fetchImpl)` → `{ ok, maxPdfSizeBytes, maxPdfSizeMb }` or `{ ok: false }`), tests `tests/unit/config/runtimeConfig.spec.ts`.
- **Out:** UI state (T-056).

## Plan of actions

1. Fetch `/config/app-config.json` with `cache: 'no-store'` (so an operator change applies without rebuild); no auth header.
2. Validate: object; `maxPdfSizeMb` is a finite number > 0 (decide and document whether non-integers are allowed — spec says numeric and positive; accept finite positive numbers).
3. Expose bytes = MB × 1,048,576.
4. Never throw out of the loader; return a typed error.
5. Tests: valid; missing file (404); invalid JSON; missing key; `"10"` string; `0`; `-1`; `NaN`; network error.
