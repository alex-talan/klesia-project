## Goal

Build the mandatory `/redirect.html` bridge as a separate Vite entry using the official `@azure/msal-browser/redirect-bridge`, and the base `staticwebapp.config.json` that never rewrites it and serves it `no-store` without COOP (AC-33).

## Context (read first)

- Webapp spec §4 *MSAL Browser v5 Redirect Handling*, DEP-02 (exact JSON), AC-33; `klesia_webapp/CLAUDE.md` *Authentication and deployment compatibility*. Check the current MSAL v5 documentation for the redirect-bridge API (record the link).

## Scope

- **In:** `redirect.html` + `src/redirect.ts` (bridge only), Vite multi-entry (`index.html`, `redirect.html`), `public/staticwebapp.config.json` (navigationFallback + `/redirect.html` route), `tests/build/build-output.spec.ts`.
- **Out:** security headers/CSP (T-069), the main auth service (T-047).

## Plan of actions

1. `redirect.html` loads `src/redirect.ts` only; `redirect.ts` imports the bridge from `@azure/msal-browser/redirect-bridge` and calls it per documentation — no Vue, no app services.
2. `vite.config.ts` `build.rollupOptions.input` with both pages; make sure the bridge chunk does not import Vue (check output).
3. `public/staticwebapp.config.json` per DEP-02: fallback rewrite to `/index.html` excluding `/assets/*`, `/config/*`, `/redirect.html`; route `/redirect.html` with `Cache-Control: no-store`; **no** `Cross-Origin-Opener-Policy` anywhere; no `/.auth` configuration.
4. Build test (`tests/build/build-output.spec.ts`, runs after `npm run build` or builds in the test): `dist/redirect.html` exists; its script bundle contains no Vue runtime marker; the config does not rewrite `/redirect.html`, sets `no-store`, contains no COOP.

## Acceptance criteria

- [ ] AC-33 passes.
- [ ] Bridge uses the official implementation; no custom code-response handling.
