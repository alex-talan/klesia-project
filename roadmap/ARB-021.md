# ARB-021 — CSP compatibility with the PDF viewer

| Field | Value |
|---|---|
| Number | ARB-021 |
| Subject | CSP compatibility with the PDF viewer |
| Description | Whether the strict CSP lets browsers display a PDF object URL in a new tab (AC-57, DEP-05) |
| Blocking | NO |
| Concerning tasks | `T-069`, `T-089` |
| Status | OPEN |

## Context

- DEM-03: the SPA opens a blank tab, fetches the PDF with the bearer token and navigates the tab to a `blob:` object URL.
- DEP-05: strict CSP (`default-src 'self'`, `object-src 'none'`, …). A document loaded from a `blob:` URL inherits the policy of its creator; depending on the browser, `object-src 'none'` or other directives may prevent the built-in PDF viewer from rendering.
- AC-57 (manual): verify in current Chrome, Edge and Firefox; *"the CSP choice, if relaxed, is documented in the README"*.

## Question

Does the strict CSP of DEP-05 allow the built-in PDF viewer in the three browsers? If not, which minimal relaxation is acceptable (and is it safe)?

## Provisional default (non-blocking)

Keep the strict CSP of DEP-05. T-089 runs AC-57 on the deployed dev environment; the result settles this arbitrage.

## Impact if settled differently

A targeted CSP change in `staticwebapp.config.json` (T-069 follow-up), its test (AC-48) and a README note; a security review of the relaxation.
