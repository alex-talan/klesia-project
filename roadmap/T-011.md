## Goal

Add a continuous-integration workflow that builds and tests the API and builds the SQL project on every push and pull request, without any Azure access. The delivery part (publish, deploy) is T-086.

## Context (read first)

- API spec HOST-11 (pipeline steps), §9 (*Delivery files*: workflow under `.github/workflows/`), `global.json` (SDK pin), `docs/deployment-app-service.md` §6.
- `klesia_api/CLAUDE.md` §8 (verification).

## Scope

- **In:** `.github/workflows/ci.yml` in `klesia_api`.
- **Out:** secrets, Azure login, deployment, SQL publish.

## Plan of actions

1. Trigger: `push` and `pull_request` on all branches (or main + PRs).
2. Job on `ubuntu-latest`: `actions/checkout`; `actions/setup-dotnet` with `global-json-file: global.json`; `dotnet restore Klesia.sln`; `dotnet build Klesia.sln -c Release --no-restore`; `dotnet test Klesia.sln -c Release --no-build` (SQL constraint tests self-skip without `KLESIA_TEST_SQL_CONNECTION`).
3. Build the SQL project: `dotnet build database/Klesia.Database/Klesia.Database.sqlproj -c Release`; upload the DACPAC as an artifact (used later by T-086).
4. Least privilege: `permissions: contents: read`.
5. Pin action major versions; no secret referenced.

## Acceptance criteria

- [ ] Workflow file is valid YAML and runs green on the current main branch (record the run URL).
- [x] It fails when a test fails (the `dotnet test` step is not continue-on-error and any non-zero test exit fails the job; recorded by local parity).
- [x] No secret, no Azure login.

## Verification

Push a branch and check the workflow run; locally run the same commands.
