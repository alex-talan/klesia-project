## Context

- API spec §3.3 (`DemandInformation`) and EXT-05: the *Required* column is an **ASSUMPTION**. Required: `brand`, `branch`, `risk_type`, `siren`, `social`, `legal_status`, `naf_code`, `idcc`, `covered_category`, `covered_amount`, `establishment_siret`, `contribution`, and at least one formula with a `name`.
- A missing required value makes the extraction `fail`.
- Changing a nullable column to `NOT NULL` later is a schema change that may block publish (data-loss blocking, backward compatibility HOST-11); changing `NOT NULL` to nullable is safe.

## Question

Confirm the list of required fields with the Document Intelligence owners and the client, using real (anonymised) BAE samples.

## Provisional default (non-blocking)

The specification's list. T-004 and T-060 implement it exactly.

## Impact if settled differently

Relaxing a field: schema change (nullable) in the SQL project + validator change (follow-up task). Tightening a field: validator change + a reviewed schema change.
