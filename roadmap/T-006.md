## Goal

Confirm that the complete six-table SQL project (SC-DB-01 to SC-DB-03) is correct, builds into the DACPAC, publishes safely over an existing database and keeps idempotent seeds.

## Context (read first)

- API spec §3.1 to §3.6, DEC-05 (seeds), DB-11 (re-publish preserves data), HOST-11 (backward compatibility), §3.6 checklist items 1, 3, 7 and 10.
- Files: `Klesia.Database.sqlproj`, `PostDeployment.sql`, `Scripts/01_RefData.sql`, `Scripts/02_User.sql`, `Properties/Azure.publish.xml`, `Schemas/*.sql`, `Tables/**/*.sql`.

## Scope

- **In:** static review and build of the whole SQL project; minimal corrections if a deviation from §3.4/§3.5 is found.
- **Out:** publishing to Azure (no environment yet; T-077/T-086), per-environment seeds (T-085).

## Plan of actions

1. Build: `dotnet build database/Klesia.Database/Klesia.Database.sqlproj -c Debug`; zero errors; list warnings.
2. Compare each table/schema file with §3.4 (names of every `PK_`, `FK_`, `AK_`, `CK_`, `DF_`, `IX_`); confirm `IX_User` on `Id` no longer exists and `IX_User_RoleId` exists.
3. `.sqlproj`: pinned `Microsoft.Build.Sql` version, `SqlAzureV12` DSP, `ModelCollation 1033, CI`, `Build Remove` for `Scripts/**` and `PostDeployment.sql`, single `PostDeploy` item.
4. `PostDeployment.sql` references `01_RefData.sql` then `02_User.sql` only.
5. Seeds: `01_RefData.sql` merges on `Code` (roles `admin`, `operational`, `guest`; statuses `pending`, `ok`, `fail` with `ok` named "Done"), never deletes; `02_User.sql` insert-only matched on `UserUniqueId`, role by code.
6. Publish profile: `BlockOnPossibleDataLoss=True`, `DropObjectsNotInSource=False`, no credential, no server name.
7. Optionally generate a deployment report/script against an **empty** model to confirm the creation order (`SqlPackage /Action:Script` needs a target; if no database is available, record *not run*).
8. Run the `check-contract` skill, Step 3 only (`database`), and attach its verdict.

## Acceptance criteria

- [ ] The project builds into `bin/Debug/Klesia.Database.dacpac` with no error.
- [ ] Every object name matches DB-06/§3.4; exactly six tables in schemas `sec`, `ref`, `dbo`.
- [ ] Seeds are idempotent and insert-only for users (reviewed and explained in the completion record).
- [ ] Publish profile keeps data-loss blocking and no drop.
- [ ] `check-contract database` step reports PASS (or every finding is fixed or turned into a task).
