## Goal

Write the hand-written mirror of the contract schemas `DemandStatus`, `Demand`, `UserDemands` and the tolerant-but-strict parser `parseUserDemands` (MODEL-01 to MODEL-03).

## Context (read first)

- Webapp spec §6.1 (*Domain types* code block, MODEL-01, MODEL-02, MODEL-03), DEM-02 (unknown status tolerated), DEM-03 (bae_link pattern is not a parse error); contract schemas; root `CLAUDE.md` rule 7.

## Scope

- **In:** `src/models/demand.ts`, `tests/unit/models/demand.spec.ts` with fixtures copied from the contract examples.
- **Out:** any other DTO anywhere else.

## Plan of actions

1. Copy the type definitions of §6.1 exactly (`KnownDemandStatus`, `Demand` with `status: string`, `UserDemands`), plus a `KNOWN_DEMAND_STATUSES` constant equal to the contract enum.
2. `parseUserDemands(body: unknown): UserDemands` — throws a typed `MalformedResponseError` (no data in the message) unless: object; `user_id`, `user_name` strings; `demands` array; each item: `demand_id` integer ≥ 1, `gk_number`, `bae_link`, `status` strings. Extra properties ignored (not copied). Pattern of `gk_number`/`bae_link` not checked here.
3. Fixtures: the `listDemands` examples from `contracts/openapi.yaml` (copied verbatim into the test, with a comment pointing to the contract).
4. Tests: valid example; empty `demands`; unknown status accepted; extra property accepted; missing field, wrong type, `demand_id` 0, 1.5, `"1"`, null body, array body → errors.
5. Run `py -3 .claude/skills/check-contract/scripts/validate_contract.py --model klesia_webapp/src/models/demand.ts` from the workspace root.
