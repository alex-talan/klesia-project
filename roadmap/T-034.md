## Goal

Provide the in-process hand-over of demand ids to the extraction worker: a bounded `System.Threading.Channels` queue behind the `IExtractionQueue` port, where enqueuing never blocks and never fails the HTTP request.

## Context (read first)

- API spec EXT-01, HOST-06, §7.2 rule 5; architecture plan §4.4 (*No message broker*), §15.3; [ARB-008](ARB-008.md) default (in-process).

## Scope

- **In:** port (`bool TryEnqueue(int demandId)` and a reader side for the worker — e.g., `IAsyncEnumerable<int> ReadAllAsync(ct)` on an Infrastructure-internal interface), `ChannelExtractionQueue` (singleton, capacity `Extraction:QueueCapacity`, `BoundedChannelFullMode.DropWrite` semantics with a `TryWrite` result), unit tests.
- **Out:** the worker (T-041).

## Plan of actions

1. Application port `IExtractionQueue.TryEnqueue(int demandId)` → `bool` (never throws for a full queue).
2. Infrastructure: `Channel.CreateBounded<int>(new BoundedChannelOptions(capacity) { SingleWriter = false, SingleReader = false, FullMode = BoundedChannelFullMode.Wait })` and use `Writer.TryWrite` (returns `false` when full, no blocking).
3. When full: log Warning *"extraction queue full; demand will be recovered by the sweep"* with the demand id only.
4. Reader side exposed only to Infrastructure (worker).
5. Register singleton in `AddInfrastructure`.
6. Unit tests: enqueue/dequeue order; capacity reached → `false` without blocking; concurrent writers.

## Acceptance criteria

- [ ] Only the demand id is carried.
- [ ] Full queue → `false` + warning, no exception, no blocking.
- [ ] Unit tests pass.
