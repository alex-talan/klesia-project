## Goal

After token and scope validation, resolve the caller's active `sec.User` from the token `oid`; an unknown **or** inactive user gets the **same** `403` as a missing scope; an infrastructure failure gives `5xx`, never `403`.

## Context (read first)

- API spec §4.2 (AUTH-02 diagram and rules), §4.3, AUTH-IMPL (*the allowlist check lives in the application layer (`DemandService`)*), AT-06, AT-07, AT-29, AT-53, AT-18; architecture plan §7.2, AP-05, AP-06.

## Scope

- **In:** a reusable Application component (e.g., `CurrentUserResolver` / `IAuthorizedUserProvider`) used by `DemandService` and by the negotiate use case; an `AccessDeniedException` (or result type) mapped by WebApi to the shared `403` body of T-019; a WebApi accessor that extracts the validated `oid` from `HttpContext.User` (never from input).
- **Out:** business queries.

## Plan of actions

1. WebApi: `ICurrentPrincipal` implementation reading `oid` from the validated `ClaimsPrincipal` (already guaranteed to be a GUID by T-018).
2. Application: `AuthorizedUserResolver.ResolveAsync(Guid oid, ct)` → `ApplicationUser` if found and `IsActive`; otherwise throws `AccessDeniedException` (single type for both causes; no message distinguishing them).
3. WebApi exception mapping (T-015 handler or a filter): `AccessDeniedException` → the **same** problem `403` as T-019 (constant title, no detail).
4. Never create or update a user; never use name, email or client-supplied id.
5. Logs: log *"access denied"* with correlation id only — no `oid`/unknown-vs-inactive distinction at Information level (a Debug-level reason without user data is acceptable).
6. Tests (with an in-memory `IUserRepository`): unknown `oid` → `403`; inactive → `403`; bodies identical to the missing-scope `403` (compare JSON without `traceId`); repository throws → `500` problem (never `403`); active → resolved user with internal `Id`.

## Acceptance criteria

- [ ] AT-06, AT-07 behaviour verified through a test-only endpoint or the first real endpoint (T-025 re-asserts).
- [ ] The three `403` causes are indistinguishable (status, headers except correlation, body except `traceId`).
- [ ] Dependency failure → `5xx`.
