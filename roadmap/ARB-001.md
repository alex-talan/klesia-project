## Context

- `architecture-plan.md` §1.2 and Appendix A say that work tracking lives in `klesia_webapp/docs/TASKS.md`; `klesia_webapp/CLAUDE.md` says the same. The file does not exist.
- The new `roadmap/` folder (root repository) covers both applications, the database and the delivery, which a file inside the webapp repository cannot do well.

## Question

Is `roadmap/` (root repository) the single work-tracking source for the whole system?

## Options

| Option | Consequence |
|---|---|
| A. `roadmap/` is the only tracker (recommended) | T-002 updates the references in the architecture plan and in `klesia_webapp/CLAUDE.md`; no `TASKS.md` is created. |
| B. Keep a per-application `TASKS.md` as well | Two trackers must be kept in sync; risk of drift. |

## Recommendation

Option A.

## Decision

| Field | Value |
|---|---|
| Decision | `roadmap/` (root repository) is the single work-tracking source for the whole system; no `TASKS.md` is created. |
| Date | 2026-11-22 |
| Decided by | Project owner |
| Follow-up tasks | — |

### Answers

1. Is `roadmap/` (root repository) the single work-tracking source for the whole system? — Yes, option A: `roadmap/` is the only tracker.

### Rationale and consequences

One tracker covering both applications, the database and the delivery avoids synchronisation and drift. Matches the recommendation. The existing task T-002 repoints the references in `architecture-plan.md` §1.2 and Appendix A and in `klesia_webapp/CLAUDE.md` to `roadmap/roadmap.md`; no new task is needed.
