# ARB-026 — Application-layer logging for demand creation

| Field | Value |
|---|---|
| Number | ARB-026 |
| Subject | Application-layer logging for demand creation |
| Description | Decide how demand creation logs a best-effort blob cleanup failure without exposing the blob URL or adding an unapproved dependency. |
| Blocking | YES |
| Concerning tasks | `T-035`, `T-093` |
| Status | SETTLED |

## Context

- T-035 requires the Application use case to catch and log a failed `IBaeDocumentStore.DeleteAsync` after a demand insert failure, without logging the blob URL.
- `klesia_api/src/Application/Application.csproj` currently references only `Microsoft.Extensions.DependencyInjection.Abstractions`; the Application layer has no logging abstraction or logging package.
- `Microsoft.Extensions.Logging.ILogger<T>` is used in WebApi and Infrastructure, but adding `Microsoft.Extensions.Logging.Abstractions` to Application or introducing an Application-owned logging port changes the dependency boundary.

## Questions

1. Which logging boundary should Application use for the demand-creation cleanup failure?

## Options

| Option | Consequence |
|---|---|
| A. Add centrally managed `Microsoft.Extensions.Logging.Abstractions` to Application and inject `ILogger<DemandService>` (recommended) | Uses the existing host logging pipeline and standard structured logging, with one additional package reference in the Application project. |
| B. Define an Application-owned logging port and implement/adapt it in Infrastructure | Avoids the Microsoft logging package in Application, but adds a custom abstraction and adapter solely for this logging path. |

## Recommendation / provisional default

Option A: use the standard logging abstraction already used by the API host and Infrastructure. Log a fixed, sanitized message and never include the blob URL, GK number or file data.

## Decision

| Field | Value |
|---|---|
| Decision | Application will use `Microsoft.Extensions.Logging.Abstractions` through a centrally managed package reference; T-093 adds the dependency before T-035 resumes. |
| Date | 2026-11-23 |
| Decided by | Architect TALAN |
| Follow-up tasks | `T-093` |

### Answers

1. Logging boundary — use the standard `ILogger<DemandService>` abstraction from `Microsoft.Extensions.Logging.Abstractions`, centrally pinned.

### Rationale and consequences

This uses the existing host logging pipeline and standard structured logging instead of introducing a custom Application-owned logging port and Infrastructure adapter. T-093 will add the centrally pinned package and Application reference. T-035 remains blocked until T-093 is complete; its cleanup warning must be fixed text and must not contain the blob URL, GK number or file data. No HTTP contract or specification changes are required.
