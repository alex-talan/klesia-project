## Goal

Implement the single CORS policy owned by the API, exactly as the contract `x-cors` and API spec §5.2 define it, evaluated before authentication so that browser preflights succeed.

## Context (read first)

- Contract `x-cors` and *CORS* section; API spec §5.2 (origins, methods, headers, exposed header, max age 600, no credentials, negotiate `negotiateVersion=1`), AT-13, AT-14, AT-32, AT-59; architecture plan §7.2 (one policy, the platform CORS stays disabled).

## Scope

- **In:** CORS policy registration and middleware order, tests.
- **Out:** App Service platform CORS (must stay disabled — T-082), SignalR resource CORS (T-078).

## Plan of actions

1. Register a named default policy from `CorsOptions.AllowedOrigins` (validated by T-009): `WithOrigins(exact origins)`, `WithMethods("GET","POST","OPTIONS")`, `WithHeaders("Authorization","Content-Type","X-Requested-With","X-SignalR-User-Agent")`, `WithExposedHeaders("X-Correlation-Id")`, `SetPreflightMaxAge(600 s)`; **never** `AllowCredentials`, `AllowAnyOrigin`, `SetIsOriginAllowed(_ => true)`.
2. Pipeline order: correlation → exception handler → `UseRouting` → `UseCors` → `UseAuthentication` → `UseAuthorization` → endpoints. Apply the policy to every endpoint (default policy).
3. Do not apply CORS to `/health` specifically (browser never calls it); harmless if the default policy applies — document the choice.
4. Tests:
   - AT-13: preflight `OPTIONS /api/v1/demands` from `http://localhost:5173` requesting `Authorization` → allowed origin echoed, methods, headers, `Access-Control-Max-Age: 600`, **no** `Access-Control-Allow-Credentials`.
   - AT-32: preflight on `/api/v1/notifications/negotiate` with `X-Requested-With`, `X-SignalR-User-Agent` → allowed.
   - AT-59: preflight on `/api/v1/demands/1/bae` with `Authorization` → allowed.
   - AT-14: preflight from `https://evil.example` → no `Access-Control-Allow-Origin`.
   - A simple `GET` response from an allowed origin exposes `X-Correlation-Id`.
   - Preflights succeed even though the routes will require authentication (no `401` on `OPTIONS`).

## Acceptance criteria

- [ ] AT-13, AT-14, AT-32, AT-59 pass (preflights may target routes not implemented yet: the CORS middleware answers preflights before routing to the endpoint — verify; if not, keep those cases in the feature tasks).
- [ ] No credentials header anywhere.
- [ ] Origins only from configuration.
