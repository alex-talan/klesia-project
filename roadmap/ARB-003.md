## Context

- The `integration-test` skill (Level 1) requires backend integration tests to validate every response body against the contract schemas, and says: *"If no JSON-schema package is already in `Directory.Packages.props`, propose one to the user instead of adding it silently."*
- `Directory.Packages.props` has no such package. The contract is OpenAPI **3.1** (JSON Schema 2020-12 dialect), in YAML.

## Question

Which packages are approved to (1) read the YAML contract and (2) validate JSON against JSON Schema 2020-12?

## Options

| Option | Notes |
|---|---|
| A. `JsonSchema.Net` + `YamlDotNet` (recommended) | Supports draft 2020-12; YAML converted to JSON in the test helper; resolves `$ref` inside the document. |
| B. `Microsoft.OpenApi` (+ readers) for parsing and `JsonSchema.Net` for validation | Official OpenAPI object model; heavier; check 3.1 support of the version used. |
| C. `NJsonSchema` | Mature, but 2020-12 support is partial. |

Versions are read from NuGet at implementation time and pinned in `Directory.Packages.props` (test projects only).

## Recommendation

Option A, test projects only.

## Decision

| Field | Value |
|---|---|
| Decision | Approve `JsonSchema.Net` and `YamlDotNet` for backend contract tests, pinned centrally and referenced only by test projects. |
| Date | 2026-11-23 |
| Decided by | Architect TALAN |
| Follow-up tasks | — |

### Answers

1. Which packages are approved to read the YAML contract and validate JSON against JSON Schema 2020-12? — Option A: `JsonSchema.Net` + `YamlDotNet`.

### Rationale and consequences

This pair directly supports the contract's YAML format and JSON Schema 2020-12 dialect while keeping the dependencies in test projects. T-023 is unblocked to implement the contract-loading and response-validation helper; T-066 can apply it after its task dependencies are complete. No follow-up task is needed. This matches the recommendation.
