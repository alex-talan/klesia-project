## Goal

Own MSAL: one `PublicClientApplication`, `initialize()` + `await handleRedirectPromise()` before anything else, redirect login when no account, API access-token acquisition (silent first, one controlled interactive redirect), display-name claims, sign-out — with no loop and no token persistence outside MSAL.

## Context (read first)

- Webapp spec AUTH-01 to AUTH-07, §4 redirect handling, AC-01, AC-18, AC-25, AC-32, AC-34, AC-44; `klesia_webapp/CLAUDE.md` rules 1 and *Authentication*.

## Scope

- **In:** `authService.ts` API: `initAuth()` → `{ status: 'authenticated', account } | { status: 'redirecting' } | { status: 'error' }`; `getApiAccessToken({ forceRefresh? })`; `recoverFromUnauthorized()` (one interactive attempt flag); `getDisplayName()` (given/family → account name → fallback provided by caller); `signOut()`; tests with a mocked MSAL.
- **Out:** UI (T-053), HTTP (T-048).

## Plan of actions

1. Config: `clientId`, `authority = https://login.microsoftonline.com/{tenant}`, `redirectUri = VITE_ENTRA_REDIRECT_URI`, cache `sessionStorage`; logger level Warning/Error in production, never logging PII/tokens.
2. `initAuth`: `await instance.initialize()`; `const result = await instance.handleRedirectPromise()`; set active account from result or existing accounts; if none → `loginRedirect({ scopes: [VITE_API_SCOPE] })` and return `redirecting`; guard against concurrent/second login (module-level in-progress flag; check `InteractionStatus`).
3. `getApiAccessToken`: `acquireTokenSilent({ scopes: [VITE_API_SCOPE], account })`; on `InteractionRequiredAuthError` → `acquireTokenRedirect` once (flag persisted in `sessionStorage` key owned by the service only for loop prevention — store no token); return **accessToken** (never `idToken`).
4. `recoverFromUnauthorized`: one forced silent refresh, then at most one interactive redirect; a second 401 → error state (AUTH-06, AC-25).
5. Display name: ID token claims `given_name` + `family_name`, else `account.name`, else the caller's `user_name` (AUTH-05).
6. Tests (`tests/unit/services/authService.spec.ts`): AC-01 (no account → loginRedirect, no token call), AC-34 (`handleRedirectPromise` awaited before any acquisition; no second login when returning from redirect), AC-18 (interaction required → one redirect; failure → error), access token not id token, AC-32 display-name order, no storage writes besides MSAL (spy on `localStorage`/`sessionStorage` except MSAL keys and the documented guard flag — or avoid the flag by using MSAL interaction state).
