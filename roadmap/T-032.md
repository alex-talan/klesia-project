## Goal

Implement, as pure Application code, the server-side validation of a demand creation: GK number, PDF size and PDF content, with error keys matching the contract (`gk_number`, `bae_file`).

## Context (read first)

- API spec §7.2 (request parts table, processing rule 2), §5.2 (`400` vs `413` vs `422`, `errors` keys), AT-24, AT-26, AT-27; contract `CreateDemandForm`, responses `BadRequest`, `PayloadTooLarge`, `UnprocessableContent`; architecture plan §9.6 (defence in depth), AP-02.

## Scope

- **In:** `CreateDemandValidator` (or equivalent) operating on an input model `{ string GkNumber, string? DeclaredContentType, long Length, Stream Content }`; PDF signature check helper; unit tests.
- **Out:** multipart parsing and part-count rules (T-036, WebApi), storage.

## Plan of actions

1. GK: exact domain rule (`GKNumber.TryCreate`, case-sensitive, no trimming) → failure → `Invalid` with `errors["gk_number"]` (safe message, English, no echo of the value).
2. Size: `Length` > `Upload:MaxPdfSizeBytes` → `TooLarge` (`413`); `Length` == 0 → `Unprocessable` (`422`).
3. Content: declared content type must be `application/pdf` **and** the first bytes must be `%PDF-` (read 5 bytes; then the stream must be rewound or the peeked bytes preserved — design the helper so the full content is still uploadable, e.g., a peeking wrapper stream or requiring a seekable buffered request stream from T-036) → otherwise `Unprocessable` with `errors["bae_file"]`.
4. Result type: `Valid | Invalid(errors) | TooLarge | Unprocessable(errors)`; no exception for expected validation outcomes.
5. File name and extension are **never** trusted or used.
6. Unit tests: valid GK/PDF; AT-24 cases (wrong prefix, lower-case, letters, missing hyphen, too short, surrounding space); size exactly at limit OK, limit+1 → too large; empty file; wrong magic bytes with `application/pdf`; `%PDF-` with `text/plain` → unprocessable.

## Acceptance criteria

- [x] Validation outcomes map one-to-one to `400`/`413`/`422` result cases with the right `errors` keys; tests cover invalid `gk_number`, oversized input, and invalid PDF outcomes.
- [x] No value echoed in messages; no file name used (safe generic messages; input model contains no file name).
- [x] Unit tests pass.
