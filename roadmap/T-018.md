## Goal

Validate Microsoft Entra **v2.0 access tokens** for this API with the standard JWT bearer middleware, rejecting with `401` every invalid case of API spec §4.3, and return the `401` as problem+json with `WWW-Authenticate: Bearer`.

## Context (read first)

- API spec §4.1 (AUTH-01, AUTH-IMPL), §4.3 (status table), §5.2 (401 body), AT-01, AT-02, AT-03, AT-05, AT-20; architecture plan §7.2, §9.2.

## Scope

- **In:** `AddAuthentication().AddJwtBearer(...)`, claim-mapping off, token checks, `401` body, tests.
- **Out:** scope policy (T-019), allowlist (T-021).

## Plan of actions

1. `JsonWebTokenHandler` with `MapInboundClaims = false` (raw `oid`, `scp`, `tid`).
2. `Authority` = `{Instance}{TenantId}/v2.0`; `ValidIssuer` = `{Instance}{TenantId}/v2.0` (exact); `ValidAudiences` = `AzureAd:Audiences` if set, else `[ClientId, "api://" + ClientId]`; validate lifetime (`exp`, `nbf`), signature; small clock skew (e.g., 2 min, document).
3. `OnTokenValidated`: reject (`context.Fail`) if `tid` ≠ `TenantId`; if a `nonce` claim exists (ID token); if `oid` is missing or not a GUID (AT-20).
4. `OnChallenge`: write problem+json `401` (`title` "Unauthorized"), keep `WWW-Authenticate: Bearer` (no error description leaking details), `traceId`; call `HandleResponse()`.
5. Register a policy-less `[Authorize]` default for now (T-019 adds the scope policy as fallback) — or temporarily apply `RequireAuthenticatedUser` as fallback so a test endpoint can be exercised.
6. Tests with `TestTokenFactory` against a test-only protected endpoint in the test host: no header, malformed header, expired, not-yet-valid, wrong signature, unsigned, wrong issuer, wrong `tid`, wrong audience (e.g., Graph `00000003-0000-0000-c000-000000000000`), ID token (`nonce`), missing `oid`, non-GUID `oid` → all `401` problem+json with `WWW-Authenticate: Bearer` and `X-Correlation-Id`; valid token → passes authentication.
7. Test that no metadata request is made in tests (static configuration from T-012).

## Acceptance criteria

- [x] §4.3 `401` cases are covered by 15 passing authentication tests: missing/malformed bearer, expired/not-yet-valid, wrong signature/issuer/audience/tenant, unsigned, ID-token nonce, missing oid and non-GUID oid.
- [x] `401` body shape is problem+json with `title`, `status`, `traceId`, and `WWW-Authenticate: Bearer`.
- [x] No custom JWT decoding is used for authorization; validation uses ASP.NET JWT bearer middleware.
