## Context

- OPEN-08g: the infrastructure code may belong to the DSI's infrastructure contract or to this project.
- Today the only IaC is `klesia_webapp/infra/azure-signalr/` (draft, never compiled), although SignalR is used mostly by the backend.
- Role assignments (*Storage Blob Data Contributor*, *Cognitive Services User*, SignalR role, database users) need elevated rights.

## Questions

1. Does the DSI provide the Azure resources (then the project only supplies requirements and verifies), or does the project write the Bicep?
2. If the project writes it: in which repository and folder (proposal: `klesia_api/infra/` for API-side resources, `klesia_webapp/infra/` for the Static Web App, or a single `infra/` in the root repository)?
3. Who runs the deployments and the role assignments (pipeline principal or DSI operator)?
4. Should `infra/azure-signalr` move next to the API infrastructure?

## Consequence for the roadmap

If the DSI owns the infrastructure, T-078 to T-083 become *"obtain the resource identifiers from the DSI and verify the configuration against the specification checklist"* (each task file describes both variants).
