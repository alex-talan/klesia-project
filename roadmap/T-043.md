## Goal

Implement the real `IDocumentExtractor` calling the custom BAE model of Azure AI Document Intelligence with the managed identity, within `DocumentIntelligence:TimeoutSeconds`, returning the EXT-04 model; then wire the extraction processing (worker + sweep) into `Program.cs`.

## Context (read first)

- API spec DEC-18, EXT-03, EXT-04, EXT-07 (categories), EXT-10, OPEN-09, §6.1 `DocumentIntelligence:*`; [ARB-005](ARB-005.md) *Decision* (answer envelope, SDK, API version); EXT-007 (model id, endpoint, samples).

## Scope

- **In:** `DocumentIntelligenceExtractor`, mapping `AnalyzeResult` → EXT-04 (if ARB-005 says so) with an explicit field table, timeout, error categorisation, registration, `Program.cs` call to `AddExtractionProcessing()`, tests with recorded/sample answers.
- **Out:** application-level retries (forbidden: SDK transient policy only).

## Plan of actions

1. Add the SDK decided by ARB-005 (expected `Azure.AI.DocumentIntelligence`) pinned centrally; client singleton with `new Uri(Endpoint)` and `DefaultAzureCredential`; `ApiVersion` from options if set.
2. `ExtractAsync(stream, ct)`: linked CTS with `TimeoutSeconds`; `AnalyzeDocumentAsync(WaitUntil.Completed, ModelId, BinaryData/stream)`; timeout → `ExtractionFailedException("timeout")`; `RequestFailedException` 4xx on the document → `document_unreadable`; 5xx/429 after SDK retries → `service_error`; unexpected shape → `malformed_answer`.
3. Mapping (if `AnalyzeResult`): one documented table field-name → EXT-04 property; types strictly checked (string, int); `formulas` from the array/object field; produce the EXT-04 JSON or the record directly — the strict rules of T-037 must apply identically (reuse the parser on a produced JSON or reuse its normalisation helpers).
4. Never log the content, the fields or the answer (EXT-10).
5. `Program.cs`: call `AddExtractionProcessing()` (T-041/T-042) and register the extractor. Verify the app starts in Development with valid configuration (DI validation).
6. Tests: mapping tests using the anonymised sample answers from EXT-007 (stored as test fixtures **only if** confirmed anonymised; otherwise synthetic fixtures with invented values); timeout and error categorisation with a mocked transport (`HttpPipelineTransport` mock or SDK test hooks).
7. Manual check (if EXT-007 resources are reachable from a developer machine with the developer's identity): analyse one anonymised sample and confirm the EXT-04 output — record as *run* or *not run*.

## Acceptance criteria

- [ ] Real adapter registered; app starts with extraction processing wired.
- [ ] Mapping and error categories tested; no value logged.
- [ ] Managed identity only (no key); timeout honoured; no custom retries.
