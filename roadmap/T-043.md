## Goal

Provide `normalizeGkNumber` (trim + upper-case) and `validateGkNumber` (`^GK[0-9]{6}-[0-9]{9}$` after normalisation), used by the modal (NEW-03).

## Context (read first)

- Webapp spec NEW-03, AC-10, AC-11; contract *GK number* convention (frontend trims and upper-cases; the API does not normalise).

## Scope

- **In:** `src/utils/gk.ts`, `tests/unit/utils/gk.spec.ts`.
- **Out:** the French error messages (component, T-056) — the util returns a reason code (`required`, `format`).

## Plan of actions

1. `normalizeGkNumber(raw: string): string` = `raw.trim().toUpperCase()`; never adds/removes the hyphen.
2. `validateGkNumber(raw)` → `{ ok: true, value }` | `{ ok: false, reason: 'required' | 'format' }`.
3. No calendar-date or checksum validation; keep leading zeros.
4. Tests: AC-10 (` gk260902-144743112 ` → `GK260902-144743112`); AC-11 cases (`GK2609-1`, `GK260902-1`, `GK260902-1447431120`, `260902-144743112`, `GK260902144743112`, `732829320`); empty and whitespace → `required`; embedded space → `format`.
