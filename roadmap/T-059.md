## Goal

Define the EXT-04 answer contract (`ExtractionAnswer` with explicit snake_case JSON names), the `IDocumentExtractor` port, and a strict parser that turns the JSON into the model or a categorised failure.

## Context (read first)

- API spec EXT-03, EXT-04 (JSON block and parsing rules: strict types, unknown properties ignored, `null`/missing/blank = absent, strings trimmed), EXT-07 (failure categories `malformed_answer`, …), DEC-21, §9; AT-42. EXT-04 stays the port contract whatever [ARB-005](ARB-005.md) decides.

## Scope

- **In:** `ExtractionAnswer` + `ExtractionFormula` records (Application), `IDocumentExtractor.ExtractAsync(Stream pdf, CancellationToken)` → `ExtractionAnswer` (or throws `ExtractionFailedException(category)`), `ExtractionAnswerParser` (Infrastructure, `System.Text.Json`), unit tests.
- **Out:** the real Document Intelligence call (T-065), validation rules (T-060).

## Plan of actions

1. Record with the 27 EXT-04 properties (`[JsonPropertyName("risk_type")]` etc.), strings as `string?`, `referrer_code`/`idcc`/`covered_amount` as `int?`, `formulas` as `IReadOnlyList<ExtractionFormula>?` (`name`, `detail`).
2. Parser: `JsonSerializerOptions` with `NumberHandling = Strict`, no case-insensitivity; unknown properties ignored; after deserialisation, normalise strings (`Trim()`; blank → `null`).
3. Failures → `ExtractionFailedException("malformed_answer")`: empty body, invalid JSON, root not an object, wrong JSON type (`"referrer_code": "abc"`, `"idcc": 12.5`, `formulas` not an array, formula not an object, string field given a number).
4. Exception messages never contain extracted values (EXT-10).
5. Unit tests: the EXT-04 example parses; each malformed case of AT-42 fails with `malformed_answer`; unknown property ignored; blank string → `null`; whitespace trimmed.

## Acceptance criteria

- [ ] JSON names exactly EXT-04; strict typing; documented normalisation.
- [ ] AT-42 parsing cases covered and passing.
- [ ] No value leaked in messages.
