## Context

- DEP-01/DEP-02/DEP-05: the SPA is a static `dist/` on Azure Static Web Apps, MSAL in the browser (platform `/.auth` **not** used), security headers from `staticwebapp.config.json` with per-environment origins in `connect-src`.
- `VITE_*` values are baked at build time, so each environment needs its own build (§3.1).
- The usual SWA GitHub action authenticates with a **deployment token** (a secret stored in GitHub), which conflicts with the "no stored secret" spirit of HOST-11; alternatives exist (e.g., deploying with the Azure CLI/SWA CLI after an OIDC login) and must be verified.

## Questions

1. SWA plan (Free/Standard), region, custom domain(s) per environment.
2. Deployment authentication: deployment token as a GitHub environment secret, or OIDC-based deployment?
3. How are the environment-specific CSP origins (API, SignalR) injected into `staticwebapp.config.json` at build time (template substitution in the pipeline vs one committed file per environment)?

## Recommendation

Standard plan; OIDC-based deployment if supported, otherwise the deployment token stored as a GitHub *environment* secret; CSP origins substituted by the pipeline from per-environment variables.
