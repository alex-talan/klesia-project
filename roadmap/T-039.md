## Goal

Implement `IDemandExtractionRepository` (Dapper): read a demand for extraction, save an extraction and set `ok` **in one transaction** with a guarded update, set `fail` with the same guard, and list stale `pending` demands — every write reporting whether it changed anything.

## Context (read first)

- API spec §9 (`IDemandExtractionRepository` responsibilities), EXT-02, EXT-06, EXT-07, EXT-09, DEC-21 (explicit field→column mapping, no global Dapper convention), §6.2 (runtime privileges: `INSERT` on the two extraction tables, `UPDATE(StatusId)` only), AT-45, AT-46.

## Scope

- **In:** port, implementation, opt-in DB tests.
- **Out:** orchestration (T-040), workers.

## Plan of actions

1. `GetForExtractionAsync(int demandId)` → `{ StatusCode, BaeLink, OwnerOid, HasInformation }` or `null`:
   `SELECT s.Code, d.BaeLink, u.UserUniqueId, CASE WHEN EXISTS (SELECT 1 FROM dbo.DemandInformation di WHERE di.DemandId = d.Id) THEN 1 ELSE 0 END FROM dbo.Demand d JOIN ref.Status s ON s.Id = d.StatusId JOIN sec.[User] u ON u.Id = d.UserId WHERE d.Id = @Id;`
2. `SaveAndCompleteAsync(int demandId, DemandInformation info)` → `bool` (true = committed): open connection, `BeginTransaction`; `INSERT dbo.DemandInformation (...) OUTPUT INSERTED.Id VALUES (...)` with **every column mapped explicitly** (`RiskType = @RiskType`, …); insert each formula in array order; `UPDATE dbo.Demand SET StatusId = (SELECT Id FROM ref.Status WHERE Code = 'ok') WHERE Id = @Id AND StatusId = (SELECT Id FROM ref.Status WHERE Code = 'pending')`; if 0 rows → rollback, return `false`; catch `SqlException` 2627/2601 on `AK_DemandInformation_DemandId` → rollback, return `false`; commit → `true`.
3. `MarkFailedAsync(int demandId)` → `bool`: guarded update from `pending` to `fail`.
4. `ListStalePendingAsync(DateTime olderThanUtc, int batchSize)` → `IReadOnlyList<int>`: `SELECT TOP (@Batch) d.Id FROM dbo.Demand d JOIN ref.Status s ON s.Id = d.StatusId WHERE s.Code = 'pending' AND d.CreatedAt < @OlderThan ORDER BY d.Id;`
5. Only `SELECT`, `INSERT`, and `UPDATE … SET StatusId` (column grant) — verify no other column is updated.
6. Opt-in DB tests: save + ok; second save → `false` (unique); guarded update on non-pending → `false`; fail path; stale listing respects `CreatedAt` and status.

## Acceptance criteria

- [ ] One transaction for information + formulas + status; rollback on lost race.
- [ ] Explicit column mapping; parameterised SQL; runtime privileges respected.
- [ ] Tests pass (DB tests skipped without the variable).
