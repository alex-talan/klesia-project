## Goal

Add `IDemandRepository.CreatePendingAsync(int userId, GKNumber gk, Uri blobUrl, ct)` returning the new `Demand.Id`, committed before returning (read-after-write, INT-12).

## Context (read first)

- API spec §7.2 rule 4 and 7, DEC-14 (`OUTPUT INSERTED.Id`), DEC-23 (`CreatedAt` set by the database), §6.2 (runtime privilege: `INSERT` on `dbo.Demand`), DB-12.

## Scope

- **In:** repository method, Dapper SQL, opt-in DB test.
- **Out:** blob upload, notification, enqueue (T-035).

## Plan of actions

1. SQL (one statement, implicit transaction):
   `INSERT INTO dbo.Demand (UserId, GKNumber, BaeLink, StatusId) OUTPUT INSERTED.Id SELECT @UserId, @GKNumber, @BaeLink, s.Id FROM ref.Status AS s WHERE s.Code = @PendingCode;`
   with `@PendingCode = 'pending'` (parameter, compared case-sensitively is unnecessary since the code is exact; keep the status resolved **by code**, never by identity value).
2. If no row is inserted (status missing) → throw a data-integrity exception (`500`).
3. Parameters typed: `GKNumber` as `AnsiStringFixedLength` length 18, `BaeLink` as `String` length 2048.
4. `CreatedAt` is never sent.
5. Opt-in DB test: insert returns an id; the row has status `pending` and a non-null `CreatedAt`; two inserts with the same GK succeed.

## Acceptance criteria

- [x] Returns the committed id through `OUTPUT INSERTED.Id`; resolves `pending` by code; omits `CreatedAt` so the database default applies. The opt-in SQL test asserts both returned ids, stored statuses and non-default creation timestamps.
- [x] Parameterized; uses only an `INSERT` statement with `SELECT` from `ref.Status`.
- [x] Unit and solution tests pass; the opt-in SQL test is skipped when `KLESIA_TEST_SQL_CONNECTION` is unset.
