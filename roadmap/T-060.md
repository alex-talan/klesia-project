## Goal

Implement `ExtractionResultValidator` (Application) with every rule of EXT-05, so that nothing invalid reaches the database (the SQL checks are a second line only).

## Context (read first)

- API spec EXT-05 (required list, format table, column-length rule), §3.3 (column lengths), AT-43; [ARB-006](ARB-006.md) default = the specification's required list.

## Scope

- **In:** validator, Luhn helper (SIREN/SIRET, La Poste exception), unit tests.
- **Out:** persistence.

## Plan of actions

1. Required (absent ⇒ failure): `brand`, `branch`, `risk_type`, `siren`, `social`, `legal_status`, `naf_code`, `idcc`, `covered_category`, `covered_amount`, `establishment_siret`, `contribution`, and ≥ 1 formula with a present `name`.
2. Formats: `siren` 9 digits + Luhn; `establishment_siret` 14 digits + Luhn + prefix = `siren`, **except** SIREN `356000000` where the sum of the 14 digits is a multiple of 5; `headquarter_nic` (if present) 5 digits and `siren`+`nic` valid SIRET by the same rule; `naf_code` `^[0-9]{4}[A-Z]$`; `idcc` 0–9999; zips 5 digits; `referrer_code` ≥ 0; `covered_amount` ≥ 1; e-mails one `@`, no space, dot in domain, ≤ 320; phone `^\+?[0-9 .()\-]{6,30}$`; `effect_date_desired` ≤ 50, no parsing; formula `name` not blank ≤ 300, `detail` ≤ 1000.
3. Length rule: every string must fit its column (`Brand` 100, `Branch` 200, `RiskType` 100, `ReferrerNetwork` 100, `Social` 300, `LegalStatus` 200, `HeadquarterAddress` 500, `HeadquarterCity` 200, `HeadquarterPhone` 30, `Email` 320, `ReferrerIdentity` 300, `ReferrerEmail` 320, `CoveredCategory` 200, `EstablishmentDesignation` 300, `Contribution` 200); too long ⇒ failure, never truncated.
4. First failing rule fails the whole answer; result carries a rule identifier only (category `validation`), no value.
5. Regexes: source-generated with timeouts or simple manual checks.
6. Unit tests for every AT-43 case: SIREN wrong checksum / 8 digits; SIRET wrong prefix / wrong checksum; NIC 4 digits; NAF `5510z`, `551Z`; `idcc` 10000; zip 4 digits; `covered_amount` 0; blank required; no formula; invalid e-mail; value longer than column; accepted: La Poste SIRET exception; an answer with only the required fields.

## Acceptance criteria

- [ ] No value in failure messages or logs.
- [ ] Pure Application code (no Infrastructure dependency).
