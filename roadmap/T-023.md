## Goal

Give backend integration tests a one-line way to assert that a response conforms to `contracts/openapi.yaml` for a given operation and status (status documented, content type, body valid against the schema), so that the API cannot drift from the contract.

## Context (read first)

- `integration-test` skill Level 1 (*Load the contract in the test and validate every response body against its schema*), architecture plan §7.1.
- [ARB-003](ARB-003.md) *Decision* (packages to use).
- The contract lives **outside** the `klesia_api` repository (`../contracts/openapi.yaml` from `klesia_api/`): decide how tests find it (walk up from the test assembly directory until `contracts/openapi.yaml` is found; if absent — e.g., `klesia_api` checked out alone in CI — skip contract assertions with an explicit reason, or copy the file as a linked test asset; record the choice).

## Scope

- **In:** packages approved by ARB-003 (test projects only, pinned in `Directory.Packages.props`), `ContractValidator` helper, its own tests.
- **Out:** applying it to every feature test (T-066).

## Plan of actions

1. Add the approved packages to `Directory.Packages.props` and to `IntegrationTests.csproj`.
2. `ContractDocument`: load YAML once, convert to a JSON node tree, resolve `$ref` within the document.
3. `ContractValidator.AssertResponse(HttpResponseMessage response, string operationId)`: find the operation; assert the status code is documented; assert `Content-Type` (`application/json`, `application/problem+json`, `application/pdf`); for JSON, validate the body against the schema (2020-12); report all errors.
4. Optional: `AssertHeaders` for `X-Correlation-Id` presence.
5. Self-tests: each `example` of the contract validates; a mutated example (missing `gk_number`, `status: "done"`, `demand_id: 0`, extra property where `additionalProperties: false`) fails with a readable message.
6. CI behaviour: document what happens when the contract file is not available (T-011 workflow checks out `klesia_api` only).

## Acceptance criteria

- [x] Helper validates the five operations' responses by `operationId` and status (`AssertResponse_ValidatesDocumentedOperationStatusAndContentType`).
- [x] Self-tests pass; every JSON response example validates and mutated `Demand` examples fail as expected.

- [x] If the contract file is absent, contract-dependent tests dynamically skip with an explicit reason; this behavior is covered by `MissingContract_ProducesAnExplicitSkipReason`.
