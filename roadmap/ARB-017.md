## Context

- HOST-11: GitHub Actions on the main branch: build, test, publish the API, **publish the SQL project with `SqlPackage`** using a deployment principal (`KLESIA_SQL_DEPLOY_CONNECTION`, Entra, no stored password), deploy (staging slot first), smoke test `/health`, keep the previous version for rollback. Azure sign-in through an **OpenID Connect federated credential** (no stored secret).
- The two applications and the root are separate Git repositories (are they on GitHub? which organisation?).

## Questions

1. Hosting of the repositories (GitHub organisation/repositories) for `klesia_api`, `klesia_webapp` and the root.
2. One deployment principal per environment? Federated credential subjects (branch, environment, tag)?
3. GitHub environments and required approvals (e.g., manual approval for production).
4. Principal used by `SqlPackage` (separate from the runtime identity) and its database role.
5. Branch protection: required CI checks before merge.

## Recommendation

One federated principal per environment bound to a GitHub environment; production requires manual approval; `SqlPackage` uses the same deployment principal added as a database user with `db_owner` (or a narrower DDL role) in that database only.
