## Context

- API spec DEC-18, EXT-03, EXT-04, OPEN-09: a custom model trained for the BAE form, called with the managed identity (*Cognitive Services User*), endpoint and model id in configuration.
- The specification **assumes** the service hands the API the EXT-04 JSON as is. A standard custom extraction model returns an `AnalyzeResult` with typed fields and confidences; in that case the mapping to EXT-04 lives only in the Infrastructure adapter and EXT-04 stays the contract of `IDocumentExtractor`.
- T-059 (port and parser) does not depend on this decision because EXT-04 is the port contract; T-065 (the adapter) does.

## Questions

1. Model id, region, endpoint and API version for each environment.
2. Exact shape of the answer: EXT-04 JSON (e.g., through a wrapper service) or `AnalyzeResult` documents/fields?
3. If `AnalyzeResult`: field names in the model, value types (string, number, array of objects for `formulas`), and the minimum confidence below which a value is *absent* (if any).
4. SDK: `Azure.AI.DocumentIntelligence` (current) — confirm.

## Recommendation

Use `Azure.AI.DocumentIntelligence` with `DefaultAzureCredential`; map `AnalyzeResult` fields to EXT-04 in the adapter with an explicit field table; no confidence threshold unless the owners require one.
