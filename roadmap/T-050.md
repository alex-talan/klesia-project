## Goal

Add `isValidBaeLink(demand)` and `fetchDemandDocument(baeLink)`: authenticated `GET {VITE_API_BASE_URL}{bae_link}` with `Accept: application/pdf`, accepted only on `200` + `application/pdf`, one 401 recovery then one retry, returning a `Blob`.

## Context (read first)

- Webapp spec DEM-03 (steps 2–3, `bae_link` rule `^/api/v1/demands/[1-9][0-9]*/bae$` and id equality), §8 *BAE PDF route*, AC-05, AC-31, AC-47, AC-49, AC-55; contract `getDemandDocument`.

## Scope

- **In:** validation helper, fetch function, tests.
- **Out:** tab handling and messages (T-055).

## Plan of actions

1. `isValidBaeLink(d: Demand): boolean` — exact regex and `Number(id) === d.demand_id`; rejects absolute URLs, `javascript:`, `data:`, `blob:`, `//host`, query, fragment, traversal, different id.
2. `fetchDemandDocument(baeLink)`: refuses invalid links (defensive); builds the URL on the API origin; GET with token; `200` and `content-type` starting with `application/pdf` → `await response.blob()`; other content type → error `malformed`; 401 → one recovery + one retry (GET is safe); 403 → forbidden; 404 → notFound; 500/503/network → server/network.
3. Never log the link, the URL or the blob.
4. Tests: AC-47 table of invalid links (each → false); valid link → exactly one request to the API origin with the access token (AC-49); 401 then 200 → two requests total; 401 twice → unauthorized; each failure status maps to its kind (AC-55); `text/html` 200 → failure.

## Acceptance criteria

- [x] AC-47, AC-49, and AC-55 logic covered; token only to the API origin.
- [x] No `href`/navigation helper exposed for `bae_link`.
