## Goal

Remove the wording drift found by the baseline audit (finding D-02 of [reports/T-001-baseline.md](reports/T-001-baseline.md)): the webapp documents speak of **two** protected REST operations, while the contract has three.

## Context (read first)

- `contracts/openapi.yaml`: protected operations `listDemands`, `createDemand`, `getDemandDocument` (+ `negotiateNotifications`).
- `klesia_webapp/docs/specs/SPECIFICATIONS.md` AUTH-03 (line 163: "on both protected REST operations"), DEM-03 (already requires the Bearer on the PDF route), AC-49.
- `klesia_webapp/CLAUDE.md` rule 1 (line 36: "to both API calls") and line 9 ("Appendix A (section 13)" — Appendix A is section 12).

## Scope

- **In:** wording of AUTH-03, `CLAUDE.md` rule 1 and the Appendix A section number.
- **Out:** any behaviour or contract change.

## Plan of actions

1. AUTH-03: replace "on both protected REST operations" with "on every protected REST operation (`GET` and `POST /api/v1/demands`, `GET /api/v1/demands/{demand_id}/bae`)".
2. `klesia_webapp/CLAUDE.md` rule 1: "to every API call (list, creation, document) and to the negotiate request".
3. `klesia_webapp/CLAUDE.md` line 9: "Appendix A (section 12)".
4. Run `check-contract` Step 2 on the webapp specification.

## Acceptance criteria

- [ ] No remaining "both protected"/"both API calls" wording.
- [ ] Appendix A section number correct.
- [ ] `check-contract` Step 2 reports no drift on these facts.
