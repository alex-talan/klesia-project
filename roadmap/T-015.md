## Goal

Every non-2xx response of an application route is `application/problem+json` (RFC 9457) with `type`, `title`, `status`, optional safe `detail`, `traceId` = `X-Correlation-Id`, and, for `400`/`422` only, optional `errors` keyed by request part name; unhandled exceptions become sanitised `500`s.

## Context (read first)

- API spec §5.2 (INT-08), §4.3 (fault is `5xx`, never `403`), §6.2; contract `components.schemas.ProblemDetails` and `components.responses.*`; architecture plan §7.2, §11.2, AP-06.

## Scope

- **In:** `AddProblemDetails` customisation (`traceId`), `IExceptionHandler` for unhandled exceptions, status-code pages for bodiless errors (`404`, `405`, `415` from the framework), a small helper to build problem responses used by later controllers, tests.
- **Out:** authentication challenge body (T-018), `403` body (T-019/T-021).

## Plan of actions

1. `services.AddProblemDetails(o => o.CustomizeProblemDetails = ctx => { ctx.ProblemDetails.Extensions["traceId"] = <correlation id>; remove "exception"/"instance" leaks })`.
2. `GlobalExceptionHandler : IExceptionHandler`: log the exception server-side (with correlation id, no sensitive data), write `500` problem with a generic French-neutral English `title` ("An unexpected error occurred."), no `detail` containing exception text, no stack trace even in Development.
3. `app.UseExceptionHandler()` and `app.UseStatusCodePages()` so that `404` for unknown routes, `405`, and framework `415` have a problem+json body.
4. Content type `application/problem+json` on every problem response.
5. A `Problems` helper (WebApi) producing standard problems: `BadRequest(errors)`, `UnprocessableContent(errors)`, `NotFound()`, `PayloadTooLarge()`, `UnsupportedMediaType()`, `ServiceUnavailable()`, with titles constant and safe.
6. Tests: a test-only endpoint throwing an exception (registered only in the test host) returns `500` problem with `traceId` equal to the response `X-Correlation-Id` and no exception text; unknown route `GET /api/v1/unknown` returns `404` problem+json (it will become `401` once the fallback policy exists — adapt the test in T-019 accordingly or call it anonymously-allowed path).
