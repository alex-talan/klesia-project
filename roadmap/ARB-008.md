# ARB-008 — Durability of background work

| Field | Value |
|---|---|
| Number | ARB-008 |
| Subject | Durability of background work |
| Description | Keep the in-process queue + recovery sweep, or Azure Service Bus behind `IExtractionQueue` (OPEN-10) |
| Blocking | NO |
| Concerning tasks | `T-034`, `T-041`, `T-042` |
| Status | OPEN |

## Context

- EXT-01: bounded `System.Threading.Channels` queue carrying only the demand id; EXT-09: recovery sweep re-queues `pending` demands older than `Extraction:StaleAfterMinutes`.
- A stopped instance leaves a demand `pending` until the sweep; Always On is mandatory (HOST-01).
- Architecture plan §15.3: Azure Service Bus behind the same port is the planned escape hatch; nothing else changes.

## Question

Does the DSI require a guaranteed hand-over (message broker), or is the bounded delay of the sweep acceptable?

## Provisional default (non-blocking)

In-process queue + sweep, as specified (DEC-23 `CreatedAt` is reusable either way).

## Impact if settled differently

New tasks: Service Bus namespace (IaC), a `ServiceBusExtractionQueue` adapter and a consumer worker, role assignment; the sweep may be kept as a safety net.
