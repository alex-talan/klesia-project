# ARB-025 — Development-only OpenAPI document route vs the contract surface

| Field | Value |
|---|---|
| Number | ARB-025 |
| Subject | Development-only OpenAPI document route vs the contract surface |
| Description | Decide how the anonymous OpenAPI document served in Development relates to the contract, which declares `/health` as the only anonymous route |
| Blocking | NO |
| Concerning tasks | `T-010`, `T-075` |
| Status | OPEN |

## Context

Found while implementing T-001 (baseline audit, finding N-01 of `roadmap/reports/T-001-baseline.md`):

- API spec §4.1 (AUTH-01): *"the only anonymous routes are the health probe and, in Development, the OpenAPI document"*. T-010 maps `/openapi/v1.json` in Development only; `check-contract` Step 4 uses that document (`--actual`).
- `contracts/openapi.yaml` describes the five operations as *"the complete HTTP surface"* and only `getHealth` as anonymous; `architecture-plan.md` §4.2 says anything else is an architectural change.
- `check-contract` says *"Code for a route that is not in the contract is always a finding"*, so a reviewer may flag the Development-only route.

## Questions

1. Is the Development-only OpenAPI document an accepted tooling route outside the contract, or must it be described somewhere?
2. If accepted: should the contract description and the `check-contract` skill mention the exemption explicitly?

## Options

| Option | Consequence |
|---|---|
| A. Accept it as Development-only tooling, outside the product surface; add one sentence to the contract description and to `check-contract` Step 4 (recommended) | Contract text change (no wire change in non-Development environments); reviewers stop flagging it |
| B. Accept it with no documentation change | Recurring false findings in `check-contract` / `integration-reviewer` |
| C. Do not expose it; produce the document at build time instead | T-010 and T-075 change; `--actual` needs a build-time generator |

## Recommendation / provisional default

Option A. Meanwhile, T-010 follows API spec §4.1 (document mapped in Development only) and reviewers treat it as allowed tooling.
