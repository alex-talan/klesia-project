## Goal

Make the GK number a link-styled `<button>` that opens the demand's PDF in a new tab through an authenticated fetch and an object URL — never through `href` or `window.open(bae_link)` — with the specified failure messages.

## Context (read first)

- Webapp spec DEM-03 (steps 1–4 and the `bae_link` rule), §8 *BAE PDF route* (messages), AC-05, AC-31, AC-47, AC-55, AC-56; `klesia_webapp/CLAUDE.md` rule 7.

## Scope

- **In:** control rendering (valid link → button; invalid → plain text), click handler, per-demand busy state, non-blocking message area (`role="alert"`) in the list panel, tests.
- **Out:** service (T-050), CSP (T-069).

## Plan of actions

1. Render: if `isValidBaeLink(demand)` → `<button type="button" class="link">` with accessible name = GK number; else plain text (status label still shown).
2. Click handler (synchronous part): `const tab = window.open('', '_blank')`; if `null` → show "Le navigateur a bloqué l'ouverture du document. Autorisez les fenêtres pour ce site, puis réessayez." and stop (no request, AC-56); else `tab.opener = null`.
3. Async: mark busy (`disabled`, `aria-busy="true"`; one request per demand max); `fetchDemandDocument(bae_link)`; success → `URL.createObjectURL(blob)`, `tab.location.href = objectUrl`, revoke within ≤ 60 s (`setTimeout` revoke); failure → `tab.close()`, show message: 404 → "Document introuvable."; 403 → French access denied; 500/503/network/other → "Impossible d'ouvrir le document. Réessayez plus tard."; never touches the list or its banner; no automatic retry beyond the service's single 401 recovery.
4. Never log or store the link, object URL or blob; clear message on next action.
5. Tests: AC-05 (tab opened synchronously before the await; one GET; tab navigated to an object URL; revoke called), AC-31/AC-47 (invalid links → no button, no `href`, no request), AC-55 (each failure → tab closed, correct message, list untouched), AC-56 (blocked popup → message, no request), double-click → one request.
