## Goal

Remove the NuGet audit advisories reported on every `dotnet build Klesia.sln` (found while verifying T-003, 2026-11-22): `System.Security.Cryptography.Pkcs` 9.0.11 — **NU1903 high** (GHSA-846f-f764-76mx) and **NU1902 moderate** (GHSA-2fmv-rv2c-59x7). `Directory.Build.props` keeps NU1901–NU1904 as warnings (not errors), so the build does not fail on them, but a high-severity advisory must not stay unaddressed.

## Context (read first)

- `klesia_api/Directory.Packages.props` (central versions; the package is **transitive**, not referenced directly), `klesia_api/Directory.Build.props` (`WarningsNotAsErrors` NU1901–NU1904).
- `klesia_api/CLAUDE.md` §3, §6; architecture plan §5 (*Version discipline*: versions read from the repository and NuGet, never guessed).

## Scope

- **In:** identify which direct package brings the vulnerable version; fix by upgrading that direct package, or by a central transitive pin of `System.Security.Cryptography.Pkcs` to a patched version (`CentralPackageTransitivePinningEnabled` or an explicit `PackageVersion`), whichever is the smallest change.
- **Out:** unrelated package upgrades; changing the audit warning policy.

## Plan of actions

1. `dotnet list Klesia.sln package --vulnerable --include-transitive` and `dotnet nuget why Klesia.sln System.Security.Cryptography.Pkcs` to find the path.
2. Read the advisories to get the patched version(s); check the NuGet MCP/feeds for the latest compatible patched version for `net10.0`.
3. Apply the smallest fix (direct upgrade if one exists, else a central pin); keep versions pinned centrally.
4. `dotnet restore`, `dotnet build Klesia.sln`, `dotnet test Klesia.sln`.

## Acceptance criteria
