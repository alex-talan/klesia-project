## Goal

Implement `DemandExtractionService.ProcessAsync(int demandId, CancellationToken)`: guard, read the blob, call the extractor, validate, store and set `ok` — or set `fail` on any failure — then publish N-2 to the owner; cancellation is not a failure.

## Context (read first)

- API spec §7.3 (EXT-02, EXT-06, EXT-07, EXT-08, EXT-10), §7.4, NOT-02, NOT-03; AT-40, AT-41, AT-44, AT-45 (unit level here; boundary checks in T-066/T-078).

## Scope

- **In:** use case, unit tests with fakes (`IDemandExtractionRepository`, `IBaeDocumentStore`, `IDocumentExtractor`, `INotifier`), an `AddExtraction(...)`-style registration method **not called by `Program.cs` yet** (see T-063/T-065).
- **Out:** hosted services (T-063, T-064), real extractor (T-065).

## Plan of actions

1. Load: `GetForExtractionAsync`; `null` (demand or owner cannot be read) → log the demand id and **stop** (there is no row to update). Status ≠ `pending` or `HasInformation` → stop silently (EXT-02). A database exception while loading → attempt `MarkFailedAsync` (EXT-07 *cannot be read*); if that also fails, the sweep retries.
2. Open the blob stream (`OpenReadAsync`) — failure → `fail` with category `storage` (Document Intelligence **not** called, AT-44).
3. `ExtractAsync(stream, ct)` — `ExtractionFailedException` → its category (`service_error`, `timeout`, `malformed_answer`, `document_unreadable`); other exceptions → `service_error`.
4. Validate (T-060) — failure → `validation`.
5. Map to domain `DemandInformation` and call `SaveAndCompleteAsync`; `false` (lost race) → stop silently, **no N-2** (AT-45); other DB exception → `fail` attempt.
6. Failure path: `MarkFailedAsync`; if it throws → log, leave `pending` (sweep retries), no N-2; if `false` → stop silently.
7. After a committed final status (`ok` or `fail`): `NotifyDemandsChangedAsync(ownerOid)` (best effort, guarded).
8. `OperationCanceledException` when `ct` is cancelled → rethrow/stop without changing the status (EXT-08).
9. Logs: demand id + category only; never extracted values or validation messages that echo them (EXT-10).
10. Unit tests: AT-40 (valid answer with two formulas → save called with all fields and formulas in order, one N-2 to the owner `oid`); AT-41 (extractor throws / times out → `fail`, N-2); AT-42 path (malformed → `fail`); AT-43 path (validation → `fail`); AT-44 (blob unreadable → `fail`, extractor not called); AT-45 (save returns false → no N-2); non-pending or already extracted → nothing called; cancellation → no status change.

- [ ] No extracted value in logs or exceptions.
