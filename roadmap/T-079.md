## Goal

Define the single user-assigned managed identity of the API and its role assignments (storage container, Document Intelligence, SignalR) — or verify the DSI-provided ones — and document the database-user creation step.

## Context (read first)

- API spec HOST-04, DEC-06, DEC-13, DEC-18, OPEN-11, §8.1; `docs/local-development.md` §2 (database user script); `docs/deployment-app-service.md` §4; [ARB-004](ARB-004.md), [ARB-015](ARB-015.md) default.

## Scope

- **In:** Bicep module for the identity (outputs: client id, principal id), role assignments with the narrowest scopes (container for storage), consumption by T-080/T-082; operator note for `CREATE USER … FROM EXTERNAL PROVIDER` + grants (cannot be done by ARM).
- **Out:** the resources themselves (T-080 to T-082).

## Plan of actions

1. Module `identity.bicep`: `Microsoft.ManagedIdentity/userAssignedIdentities`; outputs.
2. Role assignments as separate modules taking the target resource ids: *Storage Blob Data Contributor* (container scope), *Cognitive Services User* (DI resource — may be in another subscription/owner: parameterise), SignalR role per ARB-004.
3. Built-in role definition ids checked against documentation.
4. Operator procedure for the database user and grants (reference the script; T-085 may automate if ARB-017 allows).
5. Validate with `az bicep build` / what-if.

## Acceptance criteria

- [ ] Identity and assignments defined (or verified with the DSI) with narrow scopes.
- [ ] Database-user step documented and assigned to an owner.

## Verification

`az bicep build`, what-if output reviewed.
